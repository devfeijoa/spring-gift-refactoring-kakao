# 선물 서비스 사용자 스토리

2026년 11월 21일, 임시 H2 데이터베이스로 앱을 실행해 API 21개와 관리자 화면 요청 13개를 검증했다. 표에는 실제로 사용한 경로와 HTTP 상태를 적었다.

가입·로그인 API는 사용자 모두가 호출할 수 있다. 표의 **사용자(비회원 → 회원)**는 비회원이 가입하거나 로그인해 서비스 JWT를 발급받고 회원으로 서비스를 이용하는 흐름을 뜻한다. 카탈로그 관리 API와 관리자 화면도 현재 구현에서는 로그인 없이 이용할 수 있어 **사용자**로 표기했다. 관리자 스토리의 괄호는 담당 업무를 나타낸다.

## 상품을 고르고 주문하는 사람

| 누가 | 무엇을 하는가 | 왜 하는가 | 관련 요청 → HTTP 상태 | 확인한 결과 |
|---|---|---|---|---|
    | 사용자 | 카테고리와 상품 목록을 둘러본다. | 어떤 종류의 선물이 있는지 알아보고 후보를 고르기 위해 | `GET /api/categories` → 200<br>`GET /api/products?page=0&size=2&sort=id,asc` → 200 | 카테고리는 전자기기·패션·식품 3개였다. 상품 6개 중 첫 페이지에 ‘맥북 프로 16인치’와 ‘아이폰 16’이 나왔다. |
| 사용자 | 상품 가격과 옵션별 재고를 확인한다. | 원하는 구성과 수량을 살 수 있는지 판단하기 위해 | `GET /api/products/5` → 200<br>`GET /api/products/5/options` → 200 | ‘제주 감귤 5kg’은 25,000원이었고, ‘일반 감귤’ 옵션의 주문 전 재고는 50개였다. |
| 사용자(비회원 → 회원) | 이메일과 비밀번호로 가입한다. | 찜과 주문을 내 계정에 기록하기 위해 | `POST /api/members/register` → 201 | 응답에 서비스 JWT가 왔고, 회원 목록에 새 계정이 0포인트로 표시됐다. |
| 사용자(비회원 → 회원) | 가입한 이메일과 비밀번호로 로그인한다. | 이전에 만든 계정으로 내 찜과 주문을 이용하기 위해 | `POST /api/members/login` → 200 | 발급받은 JWT로 내 찜과 주문 목록을 조회할 수 있었다. |
| 사용자(비회원 → 회원) | 카카오 로그인 절차로 서비스에 접속한다. | 카카오 계정으로 내 주문 내역을 이용하기 위해 | `GET /api/auth/kakao/login` → 302<br>`GET /api/auth/kakao/callback?code=local-code` → 200 | 시작 응답은 카카오 동의 화면을 가리켰다. 테스트 인가 코드로 콜백을 호출하자 연동 계정이 생겼고, 반환된 JWT로 내 주문을 조회했다. |
| 회원 | 상품을 찜하고 내 목록에서 다시 찾는다. | 지금 사지 않아도 관심 상품을 기억해 두기 위해 | `POST /api/wishes` → 201, 같은 상품 재요청 → 200<br>`GET /api/wishes?page=0&size=5` → 200 | 감귤을 두 번 찜해도 같은 찜 ID 5가 반환됐고 목록에는 한 건만 생겼다. |
| 회원 | 내 목록에서 찜을 해제한다. | 계속 비교할 상품만 남겨 두기 위해 | `DELETE /api/wishes/5` → 204<br>`GET /api/wishes` → 200 | 주문 뒤에도 남아 있던 감귤을 찜 해제하자 내 목록이 1건에서 0건으로 바뀌었다. |
| 회원 | 옵션과 수량을 고르고 메시지를 적어 주문한다. | 보유 포인트로 원하는 구성의 선물을 구매하기 위해 | `POST /api/orders` → 201 | 감귤 2개와 ‘생일 축하해요’를 보냈더니 주문 ID 5가 생겼다. 다시 조회한 재고는 50개에서 48개로, 잔액은 75,000에서 25,000포인트로 줄었다. |
| 회원 | 내 주문 내역을 조회한다. | 주문이 접수됐는지, 수량과 메시지가 맞는지 확인하기 위해 | `GET /api/orders?page=0&size=5` → 200 | 목록에 주문 ID 5가 한 건 있었고, 옵션 ID 7·수량 2·입력한 메시지·주문 시각이 담겼다. |
| 회원(카카오 로그인) | 메시지를 적고 주문을 확정한다. | 상품과 금액을 내 카카오톡 대화방에서도 확인하기 위해 | `POST /api/orders` → 201<br>카카오 연동 요청 `POST /v2/api/talk/memo/default/send` → 200 (로컬 대역) | 별도 주문에서 카카오 대역이 ‘나에게 보내기’ 요청을 받았다. 본문에 ‘제주 감귤 5kg’, 25,000원, 입력한 메시지가 들어 있었다. |

카카오 로그인과 알림은 외부 카카오 API의 응답을 대신하는 로컬 서버로 검증했다. 실제 카카오 계정의 동의나 카카오톡 앱에서의 수신은 확인하지 않았다.

## 카탈로그를 운영하는 사람

| 누가 | 무엇을 하는가 | 왜 하는가 | 관련 요청 → HTTP 상태 | 확인한 결과 |
|---|---|---|---|---|
| 사용자(상품 운영 담당) | 기획전 카테고리를 만들고 이름을 조정한다. | 기획전 상품을 고객이 알아볼 이름으로 묶기 위해 | `POST /api/categories` → 201<br>`PUT /api/categories/4` → 200 | ‘계절 선물’이 ID 4로 생성됐다. ‘봄 선물’로 바꾼 뒤 카테고리 목록에서도 새 이름을 확인했다. |
| 사용자(상품 운영 담당) | 카테고리에 상품을 등록하고 이름과 가격을 수정한다. | 고객이 현재 판매 조건을 보고 상품을 고를 수 있게 하기 위해 | `POST /api/products` → 201<br>`PUT /api/products/7` → 200<br>`GET /api/products/7` → 200 | ‘선물 상자’를 1,000원으로 등록한 뒤 ‘봄 선물 상자’로 바꿨다. 상세 응답에는 수정 가격 1,200원과 카테고리 ID 4가 표시됐다. |
| 사용자(상품 운영 담당) | 상품에 옵션과 초기 재고를 등록한다. | 구매자가 실제로 판매할 구성 중에서 선택할 수 있게 하기 위해 | `POST /api/products/7/options` → 201<br>`GET /api/products/7/options` → 200 | 처음에는 옵션이 없었다. 추가한 뒤 ‘기본’ 10개와 ‘포장’ 4개가 조회됐다. ‘포장’을 다시 등록하자 400과 중복 안내가 왔다. |
| 사용자(상품 운영 담당) | 판매를 중단한 옵션을 삭제한다. | 상품은 계속 판매하면서 주문 가능한 구성만 남기기 위해 | `DELETE /api/products/7/options/10` → 204<br>`DELETE /api/products/7/options/9` → 400 | ‘포장’을 삭제하자 ‘기본’만 남았다. 마지막 옵션인 ‘기본’의 삭제 요청에는 제한 안내가 왔다. |
| 사용자(상품 운영 담당) | 판매가 끝난 상품과 비어 있는 기획전 카테고리를 차례로 삭제한다. | 끝난 기획전의 상품과 분류를 카탈로그에서 정리하기 위해 | `DELETE /api/products/7` → 204<br>`GET /api/products/7` → 404<br>`DELETE /api/categories/4` → 204 | 상품 상세에서 삭제를 확인했다. 이어 카테고리를 지우고 목록을 다시 조회하자 ID 4가 사라졌다. |

## 관리자 화면에서 상품과 계정을 관리하는 사람

화면 이름인 ‘회원 관리’는 등록된 계정을 관리하는 메뉴를 뜻한다. 아래의 GET은 실제 HTML 화면을 여는 요청이고 POST는 그 화면의 폼을 제출하는 요청이다. 제출 성공 시 서버가 보낸 `302`의 `Location`을 따라가 상품 목록(`/admin/products`) 또는 회원 목록(`/admin/members`)에서 결과를 확인했다.

| 누가 | 무엇을 하는가 | 왜 하는가 | 관련 화면 요청 → HTTP 상태 | 확인한 결과 |
|---|---|---|---|---|
| 사용자(상품 운영 담당) | 상품 관리 목록을 연다. | 수정할 상품을 이름·가격·카테고리로 식별하기 위해 | `GET /admin/products` → 200 | ‘봄 선물 상자’, 1,200원, ‘봄 선물’이 같은 행에 표시됐다. |
| 사용자(상품 운영 담당) | 상품 추가 폼을 열고 새 상품을 등록한다. | 고객에게 판매할 상품을 카테고리에 올리기 위해 | `GET /admin/products/new` → 200<br>`POST /admin/products` → 302 | ‘봄 선물’을 선택해 폼을 제출했다. 목록에 ‘카카오 선물’이 ID 8, 2,500원으로 추가됐다. |
| 사용자(상품 운영 담당) | 수정 폼에서 현재 값을 확인하고 상품명과 가격을 바꾼다. | 판매 정보가 바뀌었을 때 고객에게 새 조건을 표시하기 위해 | `GET /admin/products/8/edit` → 200<br>`POST /admin/products/8/edit` → 302 | 폼에는 ‘카카오 선물’과 2,500원이 채워져 있었다. 제출 후 목록에는 ‘카카오 포장’과 2,700원이 표시됐다. |
| 사용자(상품 운영 담당) | 목록에서 판매 종료 상품을 삭제한다. | 고객이 해당 상품을 더 이상 조회할 수 없게 하기 위해 | `POST /admin/products/8/delete` → 302<br>`GET /api/products/8` → 404 | 이동한 관리자 목록에서 상품 행이 사라졌고, 고객용 상세 API에서도 찾을 수 없었다. |
| 사용자(회원 관리 담당) | 회원 관리 목록을 연다. | 정보나 포인트를 변경할 계정을 찾기 위해 | `GET /admin/members` → 200 | 계정별 ID·이메일·포인트가 같은 행에 표시됐고, 해당 행에 충전 폼이 있었다. |
| 사용자(회원 관리 담당) | 회원 추가 폼을 열고 계정을 등록한다. | 이용할 사람에게 로그인 가능한 계정을 마련해 주기 위해 | `GET /admin/members/new` → 200<br>`POST /admin/members` → 302 | 이메일과 비밀번호로 등록한 계정이 ID 4, 잔액 0포인트로 목록에 추가됐다. |
| 사용자(회원 관리 담당) | 수정 폼에서 이메일과 비밀번호를 바꾼다. | 계정 소유자가 변경된 정보로 로그인할 수 있게 하기 위해 | `GET /admin/members/4/edit` → 200<br>`POST /admin/members/4/edit` → 302<br>`POST /api/members/login` → 200 | 기존 이메일을 확인하고 수정했다. 목록의 회원 ID는 그대로였고 새 이메일과 비밀번호로 JWT를 받았다. |
| 사용자(회원 관리 담당) | 목록에서 구매에 쓸 계정의 포인트를 충전한다. | 회원이 주문 금액을 포인트로 결제할 수 있게 하기 위해 | `POST /admin/members/5/charge-point` → 302<br>`GET /admin/members` → 200 | 구매에 쓴 계정의 잔액이 0에서 75,000포인트로 바뀌었다. 이 회원이 50,000원어치를 주문한 뒤 목록에는 25,000포인트가 남았다. |
| 사용자(회원 관리 담당) | 사용을 마친 계정을 목록에서 삭제한다. | 더 이상 관리할 필요가 없는 계정을 정리하기 위해 | `POST /admin/members/4/delete` → 302<br>`GET /admin/members` → 200 | 삭제 후 이동한 목록에서 테스트 계정 ID 4의 행이 사라졌다. |

필수·선택 필드, 요청·응답 JSON 예시, 관리자 폼의 입력 항목은 [요청·응답 분석](analysis.md)에 정리했다.
